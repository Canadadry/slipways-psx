## Problem Statement

Les structures — laboratoire, plateau commercial, processeur, ascension, protostar, éclat — et leurs dix tests sont du code que l'étape 3 a renommé mais dont **la prose parle encore le cart** : l'en-tête `planet_family.h` décrit chaque classe par ses digrammes (`` `s` ``, `` `et` ``, `` `hq` ``, `` `bv` ``, `` `qw` ``, `` `ly` ``, `` `qy` ``, `` `pq` ``, `` `f_` ``, `` `by` ``, `` `oe` ``, `` `hv` ``/`` `cv` ``/`` `cg` ``, `` `lt` ``…) et par des fonctions disparues (`pico8_planet_family_init`, `pico8_pi_init`, `pico8_jo_t`, `pico8_particule_prendre`, `pico8_jo_rendre_dispatch` ; 47 renvois `pico8_*` de commentaire dans les douze fichiers) ; les messages d'`assert` se préfixent d'un digramme (`"qh: the only construction key is id (ie:ldown); …"` ×4, `"nl:ly reads self.mi unguarded, unlike hj:kj"`, `"mo: the placeholder has no writer; …"`, `"ga: a burst borrows its ra …"`) ou renvoient à des initialiseurs disparus (`"pico8_planet_family_init() must run first"` ×6, `"pico8_jo_init() must run first"`) ; les tests plient leurs hachages en commentant le cart (« The cart keeps the box of `mp` » ×7, en-têtes `ie:ldown`/`mv`/`dg`).

Aucune de ces chaînes n'est **lue** : les `must_abort` des tests ne lisent que le signal, aucun `expect_fatal` ni `must_abort_saying` ne vise 3i, aucun hachage figé ne plie un texte que 4i réécrit. Ce qui demande la rigueur de l'étape 3, c'est donc la preuve de cette absence de lecteur, constante par constante.

Enfin, onze locales cryptiques à longue portée — les paramètres `gfx`/`mem`/`pos` de `burst_draw` (46), `row` de `test_life` (`test_burst.c`, 65), `gfx`/`mem`/`pos` de `test_burst_export_line_counts_the_outgoing_routes` (64, 65, 61), `pos` de `test_life` (`test_protostar.c`, 41), `poor_lab` (67), `cls` (63) et `descendants` (65) de `test_structure.c` — et deux noms qui mentent, `name`/`speed_factor` de `burst_draw`, qui tiennent l'abscisse et l'ordonnée à l'écran (laissés par 4e).
